# CPAMP-EX 主要能力

本页只列相对上游 seakee/CPA-Manager-Plus 的主要功能。上游面板适合管理 CPA 配置，但插件、凭证、配额和长期运营数据分散在不同工具里；本 fork 把它们收进同一条可验证的管理链路。

- **插件单仓与统一发布**：上游面板与插件源码分开，升级时容易出现版本和构建边界不一致。本 fork 将 OpenCode Go、Qwen 及 bailian-quota CLI 收入 providers/，由同一仓库构建，并用导入边界与 CI 约束来源和发布结果。
- **凭证、计划与身份管理**：上游缺少面向插件计划凭证的统一编辑入口，别名、掩码和宿主身份也难以保持一致。本 fork 提供统一的 /plan-credentials、Provider key 别名、插件凭证表单和受保护的凭证策略，让保存、展示、刷新都绑定到选定的真实凭证。
- **配额、余额与 Credits 观测**：上游主要展示 CPA 基础状态，无法把不同 Provider 的余额、预付费账户、Codex Credits 和凭证窗口放在同一套证据链里。本 fork 增加官方余额/预付费查询、按密钥缓存的余额、Codex Credits 与 Qwen 月度窗口，并在刷新间隔内稳定复用已确认的值。
- **请求、成本与排行分析**：上游的请求信息难以支撑长期成本核算和跨维度比较。本 fork 将请求历史、双成本、时间窗口、Provider/凭证/Key/渠道维度和排行统一到持久化分析中，保留可追溯的价格快照。
- **安全门禁与受控恢复**：上游缺少对 Provider 资金状态、凭证迁移和配额恢复的统一门禁。本 fork 在管理端加入资源能力、身份围栏、资金证据和恢复状态，先验证来源与主体，再允许刷新、自动启停或恢复动作。
- **Keeper 实时接入与 EX 品牌**：上游无法在 Keeper 订阅期间同时兼容 HTTP 采集，也没有清晰区分本 fork 的发布物。本 fork 保留订阅与 HTTP 双通道用量接入，并统一使用右下角 ex 角标标识所有自有品牌资产。

本页不替代上游使用文档；部署、配置和完整 API 说明仍以仓库其他文档为准。
