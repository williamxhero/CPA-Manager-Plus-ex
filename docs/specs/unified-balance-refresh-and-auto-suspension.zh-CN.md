# [SPEC] 统一额度刷新、独立自动暂停与 EX 图形区域定位

- 日期：2026-10-15
- 交付类型：需求规格；不代表已实现或已部署。
- 所属项目：CPA-Manager-Plus-ex（CPAMP-EX）。
- 运行时目标：本地 CPA 及其本地管理服务；本期不涉及小电脑 yosef-server，不连接、部署或验收远端服务。本地运行实例的实际配置是 provider 验收范围依据，历史配置文件不作为当前运行状态证据。
- 修订说明：按用户最新确认，余额必须 > 0.1 才恢复；取消市场覆盖率目标，仅验收本地当前 provider；运行与验收目标改为本地 CPA。
- 测试边界：用户已确认，以管理 API + 隔离 CPA 真实路由的完整链路为主，辅以适配器协议与 UI 展示测试。
- 发布：用户已授权发布到 williamxhero/CPA-Manager-Plus-ex 的 GitHub Issue，并创建、应用 ready-for-agent 标签。

### Use Case

管理员在本地 CPA 上通过 CPAMP-EX 管理多个凭证与 AI 提供商。需要清楚区分手动关闭与额度/余额触发的自动暂停，并让所有资源的额度后台每小时自动更新，同时修复图文组合品牌图片中 EX 角标覆盖文字的问题。

## Problem Statement

目前凭证的自动启停与“操作”中的手动开关缺少清晰的状态区分。代码中的自动启停虽然有独立策略和 ownership 记录，最终仍修改共用的 disabled 状态。用户无法直观看出资源是被手动关闭，还是因额度不足临时退出路由池；自动恢复也不能覆盖用户的手动意图。

凭证额度不能只靠打开页面或人工刷新保持更新。“AI 提供商”列表尚无统一余额展示与余额驱动的自动启停。用户希望将常见官方 provider 与 New API 类中转站的查询差异封装到一个自成一体的模块，而不是逐页面、逐站点复制查询代码。

启动页的品牌图片包含上方图形和下方文字，但当前 EX 生成逻辑按整张图片边界放置角标，导致文字被覆盖。其他图文组合品牌资源也需要按图形区域处理。

## Solution

1. 在每条凭证名称前展示自动启停状态标志，与“操作”中的手动开关分离。自动暂停只阻止该资源承接新的推理请求，不删除凭证，不停止额度查询，不改变其他资源、优先级或配置。
2. 保持既有手动开关的操作语义；独立保存手动意图和自动暂停。自动恢复仅解除自身暂停，不解除手动关闭或其他限制。
3. 后台每 60 分钟刷新所有现存凭证和 AI 提供商的额度/余额，不依赖页面打开，也不依赖浏览器定时器。
4. 在当前项目实现独立的额度查询模块：统一输入、输出、错误与来源语义；按本地 CPA 当前实际配置的 provider 实现必要适配，不以市场覆盖率或额外平台数量作为交付门槛。DeepInfra、OpenRouter、New API/One API 等仅在当前清单涉及时纳入必交适配。参考 conter_proj 的经验，但不依赖其桌面进程、配置目录或 Python 环境。
5. “AI 提供商”列表新增“余额”列及名称前自动状态标志。依据成功取得的可信余额执行独立自动暂停/恢复，继续保留原手动启用开关。
6. 修正自有品牌资源生成逻辑，以图形本身的右下角为锚点；同步 SVG、PNG、多分辨率图标及页面内联回退资源。

## User Stories

1. 作为管理员，我希望在凭证名称前看到自动状态标志，以便立即识别额度自动暂停。
2. 作为管理员，我希望自动状态标志与操作开关采用不同视觉和交互形式，以免误认为自动暂停等于手动关闭。
3. 作为管理员，我希望通过鼠标、键盘或触屏查看标志说明，以了解暂停原因和最近检查时间。
4. 作为管理员，我希望自动暂停后系统不再向该凭证发起新的推理尝试，以免无效请求影响服务。
5. 作为使用代理服务的调用方，我希望其他可用凭证继续按原路由规则工作，以免单个凭证额度耗尽拖累全局。
6. 作为管理员，我希望手动关闭的行为保持不变，以保留现有操作习惯和控制能力。
7. 作为管理员，我希望自动恢复永远不解除手动关闭，以确保人工决策优先。
8. 作为管理员，我希望自动暂停中的凭证继续查询额度，以便额度恢复后重新进入可用池。
9. 作为管理员，我希望所有凭证每小时后台刷新额度，以免必须打开管理页面。
10. 作为管理员，我希望未支持的额度查询明确显示“不支持”，而不是被当成零余额。
11. 作为管理员，我希望暂时查询失败时保留上次成功值并标记陈旧，以免网络故障伪造余额归零。
12. 作为管理员，我希望重启后仍保留自动暂停和刷新时间，以免重启绕过保护或造成重复查询洪峰。
13. 作为管理员，我希望能手动刷新全部或单个资源，以便充值后立即检查。
14. 作为管理员，我希望手动与定时刷新共用队列和去重，以免同时触发大量重复请求。
15. 作为管理员，我希望 AI 提供商列表直接展示余额、币种和数据状态，以便判断剩余可用资金。
16. 作为管理员，我希望 DeepInfra 的账单符号与近期消费正确换算成可用余额，以免欠款被误认为正常资金。
17. 作为管理员，我希望 OpenRouter 的账户余额和 API Key 限额被区分，以免只凭 Key 上限判断整个账户钱包。
18. 作为管理员，我希望 New API 站点可配置账户查询凭据、用户 ID 和额度单位，以便适配常见部署差异。
19. 作为管理员，我希望无需为每个同协议站点新增程序，以减少后续维护。
20. 作为管理员，我希望推理密钥不能查钱包时得到“需要配置查询凭据”的提示，以便补齐最小必要权限。
21. 作为管理员，我希望 provider 余额小于或等于 0.1 后自动暂停，以减少低余额导致的请求失败。
22. 作为管理员，我希望已暂停 provider 仅在下一次成功刷新余额大于 0.1 时解除自动暂停，以免低余额尚未越过停止阈值就反复启停。
23. 作为管理员，我希望 provider 自动暂停与手动关闭独立展示，以便准确定位不可用原因。
24. 作为管理员，我希望多个 Key 共用一个钱包时不重复累计余额，以免展示虚高。
25. 作为管理员，我希望多个独立钱包或币种不能被随意相加，以免错误关闭整个 provider。
26. 作为管理员，我希望修改、重排、重命名或删除配置时不把旧结果应用给另一资源，以免串号。
27. 作为管理员，我希望查询密钥不出现在日志、缓存、Issue、错误提示或接口读响应里，以保护账户安全。
28. 作为管理员，我希望自动任务在本地管理服务后台独立运行，以免依赖管理页面持续打开；本次不依赖小电脑服务。
29. 作为用户，我希望启动页的 EX 只覆盖图形角落，以便完整阅读品牌文字。
30. 作为用户，我希望明暗主题、不同分辨率和窄屏上的品牌资源一致，以免修好一种尺寸却损坏其他尺寸。
31. 作为维护者，我希望用同一模块对接后续常见 provider，以免解析、缓存、错误处理和调度重复散落。
32. 作为维护者，我希望通过完整路由链路证明自动暂停真正生效，以免仅有界面模拟或数据库状态测试。

## Implementation Decisions

### 1. 已确认的现状与设计边界

- 凭证自动启停目前由服务端 account-processing-policy 管理，对外兼容字段为 codexQuotaCooldownEnabled，实际还涉及其他 provider 的额度冷却；保留旧契约，不借此重命名破坏兼容。
- 当前存在 quota cooldown ownership、稳定凭证身份校验、恢复查询和失败保持停用的机制，应复用其证据与防误恢复规则，而不是建立第二套互不协调的自动操作。
- 当前凭证额度前端已有多 provider 查询、身份隔离与失败保留历史值的能力；额度快照服务并不等于全量后台主动刷新服务。
- AI 提供商页面统一展示 Gemini、Interactions、Codex、xAI、Meta、Claude、Vertex 和 OpenAI-compatible 配置；此处协议类型不等于实际计费平台，余额适配应按计费平台/端点能力选择，而不是只按页面类型选择。
- 当前 provider 手动关闭分别通过排除全部模型或 provider disabled 表达；本需求不得将余额自动暂停混入这些手动配置。
- conter_proj 已有通用 JSON 查询、DeepInfra 查询、可选浏览器会话查询、Decimal 金额、并发隔离、缓存与脱敏经验；其每日 09:00 调度、固定 ×7 展示倍率、宽松字段猜测及欠款报错行为不得不加判断直接移植。
- 当前没有仓库级领域 glossary 文件；使用既有“凭证、AI 提供商、额度窗口、余额、冷却、ownership、手动关闭”术语。遵守面板为 CPA 消费者、不是推理执行器的既有边界。

### 2. 独立额度查询模块

实现为后端 Go 深模块，提供很小的宿主接口，内部封装协议选择、认证、HTTP 查询、解析、标准化和安全错误。生产不新增对桌面 Python、Tkinter 或 conter_proj 进程的依赖。

模块只回答“该查询对象现在有哪些可信额度/余额”，不直接改路由、配置或自动策略。宿主负责资源枚举、调度、持久化与状态转换。HTTP transport、受控时钟、凭据解析器是内部可替换依赖；不把每个解析函数都暴露成宿主接口。

统一业务操作为：列举查询能力、查询一个目标、返回标准化 observation。批量刷新由宿主协调，页面不能自行实现另一套查询或自动停用规则。

- 输入：不透明目标 ID、目标身份版本、平台/协议选择、受控余额来源配置、凭据引用、超时与取消上下文。
- 输出：能力状态、数值语义、币种/单位、余额范围、额度窗口、来源身份、观测时间、查询结果及安全错误码。
- 余额范围区分 account_wallet、key_remaining、credit_balance；额度窗口不伪装成货币余额。
- 查询结果区分 success、unsupported、needs_configuration、auth_error、rate_limited、network_error、parse_error。空结果、字段缺失、NaN、无穷与失败均不是 0。
- 金额与阈值按十进制定点/精确数表示，API 使用十进制字符串；显示舍入不参与决策。
- 保留有限负数表示欠款/透支。只接受协议明确表达的 unlimited，不因负数或巨大占位上限推断无限。

### 3. 本地当前 provider 适配范围

实施开始先从本地 CPA 正在运行的实例核对当前 AI 提供商清单（包含手动关闭的条目），以脱敏资源 ID、平台/协议、账户范围和查询认证前提记录验收对象；不把旧配置文件当作正在使用的配置。交付范围仅为这份当前清单，不设置市场覆盖率、代表性样本比例或额外平台数量要求。

模块仍保持独立、可扩展，但本期只实现当前清单需要的 adapter。下表是可复用的协议设计参考，不表示必须另外接入清单之外的平台。

| 协议族 | 当前清单涉及此协议时的要求 | 约束 |
|---|---|---|
| DeepInfra | 官方账单/钱包适配 | 实施时核验官方接口、权限和单位；参考 -(stripe_balance + recent)，欠款返回负可用余额，不能报查询失败后永远保留旧正值 |
| OpenRouter | 官方账户 credits；Key 限额作为不同语义的补充 | 实施时核验官方账户与 Key API；缺少账户权限明确提示，不将 Key 额度当账户钱包 |
| New API / One API 兼容 | 账户钱包协议与 Key 剩余额度协议分别支持 | user/self 常需账户级访问凭据和用户 ID；推理 Key 不保证可用；原始 quota 换算系数必须确认 |
| 兼容 billing / JSON | 已明确文档和数值语义的已知接口 | 不盲扫大量路径；字段配置只允许受限点分路径，不允许任意脚本；不把兼容占位额度当真实钱包 |
| 现有凭证额度 | 复用或后端化既有可信查询协议 | 保留窗口、模型范围、身份与来源语义；同一轮不重复调用原生和回退来源 |

验收要求是当前清单中的 provider 逐个通过：取得真实余额、展示正确数值与单位、参与小时刷新，并验证独立自动暂停/恢复。不得通过删除失败项、只显示“不支持”或仅通过 fixture 来声称当前 provider 已通过。缺少查询权限、登录会话或可用接口时，应明确记录具体阻塞，不能伪造成功；未解决的当前清单项意味着该项尚未交付。

所有当前 AI 提供商行都接入统一状态展示。未来新增且不在本次清单中的平台可如实显示“不支持/需配置”，不因其暂不支持而扩大本次交付范围。

### 4. 配置、认证与安全

- 余额配置单独关联到 provider/计费来源，不改推理 base URL、模型、Key、优先级、冷却策略或现有手动关闭字段。
- 支持 auto、明确官方 adapter、New API/One API、受限兼容 JSON 等选择。自动识别只使用可信 host/已确认协议，不向猜测的第三方端点发送密钥。
- 支持独立只读账户查询凭据、user ID、字段与单位换算；现有推理 Key 仅在协议明确允许时使用。
- 新增查询秘密沿用项目服务端秘密存储策略；读响应只返回 configured 标志，空白保存不覆盖现存秘密，明确清除使用独立意图。不得导入 conter_proj 的真实配置或缓存。
- 默认 HTTPS、校验证书、限制响应体与总耗时、拒绝跨源重定向携带认证。余额端点属于管理员授权的明确目标，不提供任意 URL 代理；阻止云元数据地址、未授权内网目标与 DNS 重绑定，私有自建站只能通过管理员显式授权范围访问。
- 日志仅记录不透明 ID、状态和脱敏错误；不持久化原始个人响应、认证头、Cookie 或完整 Key。
- 优先使用 API 查询；若本地当前 provider 必须依赖已登录会话，可在本地经授权、可运行的连接器上接入会话型 adapter，不将其一概排除在当前 provider 验收之外。必须验证来源与账户，不导出 Cookie、不自动登录、不绕过验证码。没有授权会话或连接器时明确记录该项阻塞，不能擅自接管本机浏览器，也不要求使用小电脑。

### 5. 身份、数据模型与一致性

逻辑实体如下；优先扩展现有存储边界，避免把金额强行写入只接受百分比窗口的旧字段：

| 实体 | 必要信息 |
|---|---|
| ResourceRef | 资源类型、稳定不透明 ID、CPA 实例范围、身份版本、删除状态；凭证保留现有严格身份约束 |
| BalanceSource | adapter、受控 endpoint、凭据引用、账户范围、币种与换算规则、配置版本 |
| Observation | 查询 ID/版本、来源范围、金额字符串或窗口集合、语义、成功时间与来源证据 |
| RefreshState | 最近尝试、最近成功、最近结果/安全错误、下次执行、运行租约、批次 ID |
| AutoSuspension | 独立暂停标志、reason、owner、证据 observation、发生时间、版本、恢复记录 |
| Policy | 自动策略启用、锁定/来源、余额阈值及单位；凭证与 provider 策略分域 |

- 不以数组下标、显示名称、明文 API Key 或前端渲染 key 作为持久主键。优先使用宿主稳定身份，缺失时由后端建立保守的身份绑定；歧义时拒绝自动动作。
- observation 仅能应用到同 CPA 实例、同身份版本、同余额配置版本的目标；慢响应不能覆盖更新结果。
- Key、账户或余额语义改变时旧 observation 不再用于决策；单纯名称/显示倍率变化不能串换钱包。
- 同一真实钱包只有一个 BalanceSource，可关联多行；仅在账户范围已确认时去重，不能因相同 host 就认定同一账户。
- 多独立钱包 provider 显示明细；同币种、范围明确且互不重叠才允许汇总，不跨币种相加，不重复累计共享账户余额。
- 无法给多 Key provider 建立完整计费范围时禁止自动关闭整个 provider。范围明确时，只有全部可路由资金来源均有当前可信余额且均 ≤ 0.1 才暂停整行；已有整行暂停后至少一个明确可路由来源成功刷新 > 0.1 才可解除该余额暂停。

### 6. 手动关闭与自动暂停状态机

新增与手动状态正交的自动暂停门禁。有效路由资格同时满足：既有手动/配置许可、没有自动暂停、并满足原有健康与路由约束。

- 凭证/provider 名称前的标志是状态显示，不是另一只与操作开关长得相同的滑动开关。
- 至少区分：自动策略未启用、自动监测正常、自动暂停、自动状态不可用；同时存在手动关闭时可同时表达，不互相覆盖。
- 策略设置入口独立存在；保留现有凭证全局策略及环境锁，provider 余额策略独立控制，不能开启 provider 功能时偷偷更改凭证策略。
- 已启用的自动策略一旦得到可信触发证据必须执行真实门禁；首次上线 provider 自动策略需明确启用，不在迁移时静默关闭生产资源。
- 手动开关始终表达既有手动意图：手动关闭在自动恢复后仍关闭；手动开启不绕过仍生效的余额暂停。
- 关闭自动策略保留现有“停止自动动作、不自动恢复历史暂停”的语义；需要清除历史自动暂停时使用明确操作，不隐式批量恢复。
- 暂停阻止新请求、重试、故障转移选中该资源；暂停前已在途请求不强制中断。运维读取、余额查询和明确授权的诊断不受影响。

#### Provider 余额转换规则

按用户最新确认，停止与恢复使用同一个边界：余额 ≤ 0.1 暂停，余额 > 0.1 才恢复。恰好 0.1 不恢复：

| 旧自动状态 | 本次新鲜、成功且范围匹配的余额 | 新自动状态 |
|---|---|---|
| 未暂停 | ≤ 0.1（含负数、0、恰好 0.1） | 自动暂停 |
| 未暂停 | > 0.1 | 保持未暂停 |
| 已暂停 | > 0.1 | 解除本策略自动暂停，手动状态不变 |
| 已暂停 | ≤ 0.1 | 保持暂停 |
| 任意 | 失败、不支持、缺认证、陈旧缓存、语义/身份不明 | 不因这次查询改变自动状态 |

一次 observation 对一个目标最多触发一次转换，重复消费、页面重载、服务重启不能再次评估同一证据来反向转换。下一次独立成功刷新允许重新判断。

阈值默认按来源已经确认的原生货币单位解释：0.1 USD 和 0.1 CNY 分别判断，不隐式汇率换算；非货币额度不能直接套用金额阈值。UI/策略说明显示单位。

**边界稳定性：** 余额持续位于 (0, 0.1] 时持续暂停，不得因下一轮余额仍为正数就恢复。只有新的可信成功观测超过 0.1 才恢复；手动关闭仍不受自动恢复影响。

#### 凭证额度转换规则

继续使用各 provider 已有可信额度耗尽/恢复判据，不将货币 0.1 应用到百分比、token 或请求窗口。额度耗尽暂停后，仅在权威查询确认适用窗口恢复时解除；重置时间只是复查计划，不是必然恢复证据。未知/失败保持暂停，不靠一条普通 429 或网络错误推断耗尽。

### 7. CPA 路由契约与跨项目边界

管理服务数据库状态和前端过滤不能证明推理请求不会再尝试资源。实施必须先核验目标 CPA core 的实际能力：能否在不改手动 disabled/排除模型配置的情况下，对稳定目标应用独立自动暂停，并对真实调度、重试和故障转移生效。

- 优先复用 core 已有等价能力；没有则必须增加 core 的独立、可持久/可重放的自动暂停契约与管理能力。
- core 不支持时，API 明确返回 capability unavailable，UI 不得伪装为已自动保护；这是完整交付阻塞，不以只做标志或暗改手动开关代替。
- 门禁写入要返回确认版本/有效状态。门禁失败不报告成功；持久化与 core 不一致应进入可观察的待协调状态，幂等重试，不能让 UI 声称已保护而 core 继续选中。
- 重启时在正常承接流量前恢复/校验既有自动门禁；CPA 连接变化时按实例隔离，不能把上一个实例的暂停重放到另一个实例。
- 若修改属于独立 CPA core 仓库，实施必须通过 cross-project-delegation 在目标项目上下文完成，本项目仅定义契约、协调与验收；不得在本项目会话直接改另一个仓库。
- conter_proj 本期只读参考，不修改。未来让桌面便签消费共享模块需要独立迁移任务和该项目的授权执行上下文。

### 8. 每小时刷新策略

- 本地管理服务的后台 worker 统一调度：每个资源正常每 60 分钟到期一次，采用可解释的稳定错峰，而非要求全部整点同时发请求。
- “所有凭证/所有 provider”包含手动关闭、自动暂停、未在当前分页或筛选中的资源。缺查询能力的资源记录 unsupported/needs_configuration，不发无意义探测，也不伪造余额。
- 启动时对缺观测或已到期目标补刷一轮；停机错过多轮只合并补刷一次，不追赶所有历史小时。
- 定时依据持久化下次执行/最近尝试安排，不能因最近成功很久以前就每次 tick 重试。失败保留最近成功数据和时间，并将失败/陈旧状态单独更新。
- 全局初始并发上限 4，同一计费来源 single-flight；按来源执行速率限制。单目标默认总超时 15 秒、硬上限 60 秒，响应体上限 2 MiB；重试计入总预算，429 遵守 Retry-After。
- 单目标失败不阻塞其他目标；大批次允许分片进度，但必须覆盖批次快照内全部资源，不能只刷新前一页。
- 多标签页、手动/定时触发共用任务去重。手动刷新不永久推迟原定后台周期；进行中的重复请求返回同一任务状态。
- 与已有冷却恢复探针、巡检和前端手动查询共享来源级去重/缓存，不重复消耗上游接口。该刷新服务不依赖推理使用事件开启。
- 不使用模型生成请求来测额度，不消耗推理额度，不自动执行领取、充值或重置 credit 操作。

### 9. 管理 API 契约

沿用既有管理员认证、错误封装与能力发现习惯；新增 API 为增量契约，既有手动开关 API 和 account-processing-policy 兼容不变。

| 操作 | 语义 |
|---|---|
| GET 额度刷新能力 | 返回支持的 adapter、查询/路由门禁能力、配置要求、调度可用性及策略锁定状态 |
| GET 资源额度状态 | 按稳定 ID 批量返回最近成功观测、最近尝试状态、币种/范围、陈旧标志、自动暂停、手动状态、有效路由状态和下次刷新；不在 GET 时隐式访问上游 |
| POST 刷新任务 | 支持全部、凭证、provider、指定稳定 ID；返回 202、任务 ID、去重结果，拒绝任意未授权 URL |
| GET 刷新任务 | 返回排队/执行/完成、目标计数、成功/失败/不支持计数和逐目标安全结果；部分失败不伪装全成功 |
| PUT/PATCH 余额来源配置 | 带配置版本更新 adapter、单位与秘密引用；冲突返回 409；空白秘密保持原值 |
| PATCH provider 自动策略 | 独立于手动开关；返回已持久化值、有效值、来源、锁定与时间；失败不乐观显示成功 |

API 返回的 effectiveEnabled 由实际 gate 确认及既有约束共同推导，不仅由数据库 bool 推导。自动事件记录包含目标、reason、证据 ID、金额/单位、旧新状态、core 应用结果和时间，均不得带秘密。

### 10. UI 与 EX 资产规则

- 凭证列表/卡片在名称文字之前放自动标志，不改可复制的名称文本；排序、搜索、选择和详情定位行为保持兼容。
- 标志用图形 + 明确可访问名称/说明表达状态，不能仅靠颜色；说明包括原因、最近成功查询/失败、下次检查，未知重置时间不伪造恢复倒计时。
- AI 提供商新增“余额”列：已知余额显示金额及币种；无历史显示“未获取”；未知能力显示“不支持”或“需配置”；失败显示旧值并明确“上次成功/已过期”。无限仅在明确语义下显示。
- 多钱包显示真实范围及详情入口，不把不完整数据误呈现为完整 provider 总额。窄屏保留余额字段、自动标志和手动操作，不让列挤掉核心控件。
- provider 名称前采用与凭证一致的自动状态语言，原启用开关仍仅表达手动状态。
- EX 仅用于 CPAMP 自有品牌资产，不扩展到第三方 provider 商标。为每类资源记录图形区域、文字保留区域及角标锚点；竖排图文组合与横排图文组合均不能用整图右下角替代图形右下角。
- 纯文字 wordmark 不加覆盖文字的 EX；图形已带 EX 时避免侧栏 DOM 标签叠成双角标。
- 修改可复现的品牌生成源，从干净原图生成，不能只改输出 PNG 或在登录页临时盖住旧角标。同步 SVG、各档 PNG、ICO 帧、touch icon、服务端副本及内联回退，保证无文字遮挡、无裁切、无重复。

### 11. 迁移、兼容与交付阶段

1. 品牌定位修复可独立交付，不依赖余额模块。
2. 先确认额度模块契约、本地当前 provider 验收清单与本地 core gate 能力；缺 core 能力先完成目标项目依赖。
3. 增量建立资源身份、余额配置、观测、任务和自动门禁状态；保留历史额度快照与其他监控数据，不重建或清空生产数据库。
4. 上线后台刷新与只读展示，再显式启用 provider 自动策略；完整链路通过后方可认为自动保护交付完成。
5. 迁移历史 quota cooldown 时，仅对 ownership、身份与手动意图均可确认的记录转为自动门禁；先确认新门禁生效，再处理历史自动写入的共用 disabled。不确定的历史停用保持原状并标记待确认，不能推断为自动停用后批量开启。
6. 不修改手动关闭的配置规则、已有环境锁、插件 ABI、额度窗口/订阅含义。读旧数据时缺新增字段视为未知，不视为余额零。
7. 回退前必须处理 core gate 与新状态格式兼容，不能降级后静默放行已暂停资源；提供备份、升级检查和回退步骤。生产变更需后续实施阶段授权与隔离演练，本次规格发布不构成部署授权。

## Testing Decisions

### 测试原则与主要边界

以用户可观察行为为准，不依赖内部函数调用次数、私有字段布局或 CSS 哈希类名。主要 seam 是管理 API 驱动的隔离运行时：真实管理服务、临时持久层、隔离 CPA core 和可控协议上游。用户已确认采用此边界。

测试时 mock 的是外部平台网络与时钟，而不是被验收的自动状态转换和实际 CPA 选择器。适配器协议测试与少量 UI/资产测试作为补充，不为每层重复创建 mock 契约。

沿用既有管理 HTTP 集成测试、自动 worker ownership/失败保持停用测试、额度身份隔离测试、React 页面行为测试和品牌生成完整性检查。自动化回归测试使用合成 Key、独立数据库和本地隔离端口，不干扰本地正式请求；最终针对本地 CPA 当前 provider 做授权的真实余额查询与受控功能验收。不连接小电脑，也不以远端运行结果作为完成条件。

### 验收用例

1. 两条可用凭证 A/B：可信证据令 A 自动暂停后，跨新请求、重试、故障转移均不再选 A，B 正常；不改变 A 的手动开关意图。
2. 暂停后额度查询仍到达 A 的管理查询源；权威恢复观测解除自动暂停后可重新路由。
3. 手动关闭 + 自动暂停同时存在时，自动恢复只清自动状态，仍不选该资源；手动开关原 API 行为回归通过。
4. provider 余额 0.1、0、负数均暂停；0.100001 不触发暂停。已暂停时下一次成功余额为 0.000001、0.05 或恰好 0.1 均保持暂停，只有 > 0.1（例如 0.100001）才恢复；同一次证据不能重复触发动作。
5. 持续 0.05 或持续 0.1 的多轮刷新始终保持暂停，不反复启停；跨过边界的每次转换均有新鲜可信证据，十进制判定不受显示两位小数影响。
6. 查询失败、401、429、超时、字段缺失、HTML、success=false、NaN/Infinity、不支持、陈旧值均不伪造零或恢复；历史值和最后成功时间保留。
7. 本地当前 provider 涉及的协议使用脱敏 fixture 验证数值、认证和账户范围；若清单包含 DeepInfra、OpenRouter 或 New API，分别覆盖其账单符号/欠款、账户与 Key 权限或单位/用户 ID，不接受占位 billing 上限。清单之外的平台不构成本期必交项。
8. 多 Key 共享钱包不重复累加；不同钱包、不同币种和部分未知配置不错误关闭整行。
9. 浏览器全部关闭、页面切换或不登录面板时，服务端推进时间 60 分钟仍覆盖全部资源；跨分页、自动暂停和手动关闭的目标均被枚举。
10. 重启只补刷到期目标；漏掉多小时只补一轮；失败不会每个 tick 洪泛；重复手动/定时任务去重；同源并发和全局上限生效。
11. 配置重排、重命名、换 Key、删除重建、切 CPA 实例及迟到响应不会串号；版本冲突明确失败。
12. core 不支持独立 gate、gate 写入失败、持久层失败、重启重放失败可观察且不谎报“保护成功”；成功暂停重启后不会暂时重新进入池。
13. 新旧 cooldown 迁移、ownership 不明、自动期间再次手动关闭及并发管理写入不误恢复；回退演练不丢数据。
14. 列表/卡片自动标志位于名称前；手动开关状态不被自动暂停伪装改写；余额列在桌面/窄屏、明暗主题和键盘操作下可理解。
15. EX 图形区域与文字保护区做几何断言并进行渲染检查；启动 splash、登录卡、侧栏、纯 wordmark、favicon/touch icon 各档无文字覆盖、无裁切、无双角标；生成器检查和资源副本一致性通过。
16. 请求、响应、日志、任务状态和错误提示使用秘密诱饵验证不泄露；跨源 redirect、受限内网、账户身份不符不发送/泄露凭据。
17. 本地当前 provider 验收清单逐项通过真实余额查询、金额/单位展示、小时刷新及独立自动暂停/恢复验证；逐项记录成功证据或具体阻塞，不能以“不支持”、仅 fixture 通过或移除失败项充作完成。不设置市场覆盖率或平台数量指标。
18. 最终在本地 CPA 的授权窗口核验实际运行实例、配置和门禁效果，并进行受控功能验收；不连接、部署或验收 yosef-server，不把历史本地配置当作当前实例状态。
