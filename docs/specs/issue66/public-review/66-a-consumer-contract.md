# [SPEC 66-A] 独立自动暂停消费契约、协调与安全迁移

- 父需求：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。本稿仅细化公开父需求，不替代或缩减其验收。
- 交付类型：规划与消费契约提案；不是现有 core 能力、源码调查、实现、测试或部署证明。
- 边界：CPAMP-EX 是管理消费者。目标 core 的接口位置、内部实现及实际支持范围由目标项目 owner 核实；不得据本提案推断已有或缺少某项能力。

### Use Case

管理员希望额度／余额触发的暂停真正阻止新的推理尝试，同时保留人工关闭、其他限制及额度复查，并在重启、升级和回退中维持保护。

## Problem Statement

公开父 #66 要求把人工意图与自动保护分离。管理数据库标记或前端展示不能单独证明路由已经停止使用该资源；目标 core 是否具备等价能力，需要以实际能力与隔离路由证据确认。历史停用原因不明确时，也不能通过迁移批量开启资源。

## Solution

定义并消费独立自动暂停契约，以稳定目标、版本约束、可确认结果和可重试协调表达保护。缺能力、失败或结果不明如实显示不可用／待协调，不暗改人工 disabled 或模型排除配置。自动恢复只解除自身暂停；暂停中的管理额度查询保持可用。

## User Stories

1. 作为管理员，我希望人工关闭与自动暂停分别保存，以便恢复不覆盖人工决定。
2. 作为调用方，我希望暂停资源不再承接新请求，以便避免无效尝试。
3. 作为调用方，我希望重试及故障转移也遵守暂停，以免绕过保护。
4. 作为调用方，我希望暂停前已准入请求可以完成，以免无故中断响应。
5. 作为管理员，我希望暂停中的额度查询仍可执行，以便取得恢复证据。
6. 作为管理员，我希望恢复只清本策略限制，以便不影响其他限制。
7. 作为管理员，我希望实际门禁未确认时不显示已保护，以便理解真实风险。
8. 作为管理员，我希望实例切换不重放另一个实例的暂停，以免错误绑定。
9. 作为管理员，我希望换账户、换 Key 或删除重建不沿用旧证据，以免串号。
10. 作为维护者，我希望重复操作可安全协调，以便处理超时与结果不明。
11. 作为管理员，我希望重启承接流量前恢复保护，以免短暂重新放行。
12. 作为管理员，我希望迁移只处理 ownership 与人工意图可证明的记录，以免误开启资源。
13. 作为管理员，我希望降级不能丢失暂停状态，以便安全回退。
14. 作为维护者，我希望跨项目能力由对应 owner 交付，以便保留项目边界及可复验证据。

## Implementation Decisions

以下均为由父 #66 的身份、一致性、路由、兼容与迁移要求导出的**消费端约束提案**，不是对 core 内部结构或接口版本的陈述。

1. 能力发现需能说明独立自动暂停是否可用、目标类型、当前运行模式的覆盖及恢复就绪状态。版本号或接口返回成功不能替代路由证明；不支持则明确 unavailable。
2. 目标清单包括人工关闭资源。消费端绑定稳定不透明 ID、CPA 实例、身份版本；删除重建和 provider 成员变化必须使歧义绑定失效。不使用显示名称、数组位置、明文 Key 或前端渲染 key 作持久主键。
3. 需要的业务操作是读取能力、读取目标及其独立状态、提交带目标版本与证据的暂停／恢复、查询不明结果。具体 URL、字段拼写及版本方案由目标项目确认，不预设其现有路由或持久化结构。
4. 写请求应带预期目标／状态版本、策略归属、证据标识及幂等操作标识；冲突拒绝，重复同内容操作不重复转换，同标识不同内容拒绝。恢复不得覆盖更新证据产生的暂停。
5. 人工状态、自动策略意图、持久状态和门禁实际应用确认分别表达。不同自动归属的限制不能互相解除；不把“本策略已解除”宣称为全局可路由。
6. 超时／持久化失败／门禁应用失败进入可观察待协调；仅在真实应用得到确认后宣称已保护。协调可重试，不伪称跨进程原子事务，不回退写人工 disabled／排除模型。
7. 门禁覆盖目标当前实际支持的所有新推理尝试，包括新请求、重试和故障转移；若存在流式或长连接，其新的推理尝试亦须遵守。明确确认生效边界：此前已准入请求可完成，此后不能新增被禁止尝试。此要求不预设任何内部选择器或业务入口。
8. 额度查询与明确授权运维读取不被推理暂停阻断；不得提供可由未授权调用方伪造的绕过方式。普通成功、计时到期或查询失败不能代替可信恢复证据。
9. 重启在接受受影响流量前恢复／校验保护；恢复失败保持受影响目标不就绪／拒绝新尝试，状态可观察。不以排除实际使用模式来缩小验收范围。
10. 保留父需求公开的旧手动接口、codexQuotaCooldownEnabled 兼容字段及环境锁。关闭自动策略停止新动作，不隐式恢复历史暂停。
11. 历史迁移仅处理归属、身份与人工意图均可确认的记录；先确认新门禁，再处理旧自动写入的共用停用。模糊记录保持原状并标待确认；并发人工关闭不能被抹去。
12. 增量迁移保留数据，先备份并演练。旧版本无法理解保护状态时必须明确阻断不安全回退，而非静默丢门禁放行。
13. 目标 core 的必要修改通过 cross-project-delegation 交目标项目授权上下文；CPAMP-EX 只实现自身消费端并接收固定版本、能力说明、真实路由与恢复证据。本轮不发起实现。

## Testing Decisions

主 seam 沿用父 #66：管理 API→真实管理服务／临时持久层→隔离真实 CPA core→受控上游。仅替换外部网络、时钟与故障注入，不 mock 被验收状态机或实际路由。复用父需求指出的既有 HTTP、ownership、身份隔离与失败保持停用测试组织。

- 两资源 A/B：暂停 A 后新请求、重试、故障转移不再尝试 A，B 正常；暂停前已准入请求完成，额度查询仍到达来源。
- 人工关＋自动暂停并存；人工开不能绕暂停，自动恢复不清人工关或其他归属限制；可信恢复与普通计时／错误区分。
- 实例切换、换账户／Key、重排、删除重建、成员变化、重复与迟到证据、并发版本冲突不串号。
- 门禁不可用、写失败、持久层失败、确认丢失、启动恢复失败可观察，不假报成功或短暂放行；重启后可协调。
- 迁移模糊 ownership、人工并发、部分失败与回退演练不误恢复、不丢数据；管理鉴权与秘密诱饵通过。

对应父验收 1–3、11–13、16；并为 17–18 提供真实门禁证据。相关其余父验收由 B／C／D 联合完成，不因本包通过而取消。

## Out of Scope

本轮不实现、不访问 live、不读或导出秘密、不改其他仓库、不部署／重启／合并／关闭 issue；不连接 yosef-server。此包不拥有金额解析、刷新调度或品牌生成，不改变人工规则、优先级、插件 ABI 与原健康约束。
