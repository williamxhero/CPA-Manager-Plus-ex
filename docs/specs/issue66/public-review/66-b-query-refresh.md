# [SPEC 66-B] 统一安全额度查询与全量小时刷新

- 父需求：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。仅派生公开父需求，全部相关验收保持。
- 交付类型：规划与宿主消费契约提案；不是现有源码、当前库存、查询成功或部署证明。
- 与 66-A 共享目标身份约束；只读查询／调度不以真实门禁已交付为前提，自动保护仍须消费 A 的确认能力。

### Use Case

管理员关闭浏览器后，仍需要全部现存凭证与 provider 按小时刷新可信额度／余额；手动刷新共享同一任务，错误不会把余额变零，也不会泄露认证材料。

## Problem Statement

公开父 #66 要求统一主动查询与后台刷新，不能用页面定时器、当前页数据或被动快照代替。协议、账户权限、单位和钱包范围不同，未经确认的数值不能直接用作余额或恢复证据。

## Solution

以独立 Go 深模块封装协议、认证、解析与安全错误；宿主统一枚举、持久化和调度。查询模块只返回标准化观测，不改路由或策略。按实际当前清单交付必要协议，失败保留旧成功值并明确陈旧／需配置／不支持。

## User Stories

1. 作为管理员，我希望浏览器关闭后仍每小时刷新，以免依赖页面常开。
2. 作为管理员，我希望人工关闭、自动暂停与分页外资源也被覆盖，以免漏刷。
3. 作为管理员，我希望手动刷新全部或单资源，以便充值后立即核实。
4. 作为管理员，我希望人工、定时和恢复复查共用来源执行，以免重复查询。
5. 作为管理员，我希望金额与额度窗口分开，以免百分比变成货币。
6. 作为管理员，我希望账户钱包、Key 限额和 credit 范围明确，以免错误判断资金。
7. 作为管理员，我希望有限欠款如实呈负数，以免旧正值掩盖债务。
8. 作为管理员，我希望只有协议明确时才显示无限，以免把占位上限当余额。
9. 作为管理员，我希望失败保留旧值和成功时间，以便识别陈旧状态。
10. 作为管理员，我希望认证不足具体提示需配置，以便补齐最小权限。
11. 作为管理员，我希望共享钱包不重复累计，以免余额虚高。
12. 作为管理员，我希望多钱包、币种和不完整范围不能随意求和，以免误停整行。
13. 作为管理员，我希望身份或来源变化后旧响应失效，以免串号。
14. 作为管理员，我希望来源配置不泄露秘密或形成任意 URL 代理，以便安全运维。
15. 作为管理员，我希望重启合并补刷而非追赶每个历史小时，以免洪泛。
16. 作为管理员，我希望真实当前 provider 逐项有验收记录，以免 fixture 或“不支持”冒充交付。

## Implementation Decisions

1. Go 模块的宿主业务操作仅为列举能力、查询目标、返回标准化 observation；协议、认证、HTTP、解析和安全错误封装在模块内。宿主负责库存、调度、持久化与策略；不依赖桌面进程或配置目录。
2. 输入绑定稳定不透明目标、实例、身份／来源配置版本、受控协议与 endpoint、凭据引用、超时／取消。输出能力、金额／窗口、币种／单位、账户范围、来源身份、观测时间及安全结果；这些是接口语义，不规定私有实现字段布局。
3. 金额采用有界精确十进制表示，API 为字符串；显示舍入不参与判定。有限负数保留；NaN／Infinity／缺字段／失败不等于零，只有明确协议语义才可标 unlimited。
4. 分开 account_wallet、key_remaining、credit_balance 和额度窗口；不把金额强塞进旧百分比窗口字段。优先扩展既有存储边界，保留历史快照和监控数据。
5. 查询结果区分 success、unsupported、needs_configuration、auth_error、rate_limited、network_error、parse_error。最近尝试与最近成功分离，失败保留旧值和时间并更新陈旧状态。
6. 身份／来源配置变化、换 Key／账户、删除重建或切实例使旧观测不得参与决策；迟到响应不能覆盖新结果。名称或顺序不是持久身份，歧义绑定拒绝自动动作。
7. 一个已确认真实钱包对应一个 BalanceSource，可供多行引用；仅凭同 host 不能认定共享账户。来源级 single-flight 必须区分账户、权限与来源配置版本，不错误共用结果。
8. 多来源展示明细；只有同币种、互不重叠且完整的范围才可汇总。不跨币种求和，不把部分已知展示为整行完整余额。
9. Hermes 经安全授权通道核对本地当前实例清单，包括人工关闭条目，记录脱敏资源、平台／协议、账户范围、单位和查询前提；历史配置不是运行证据。未核实项明确阻塞。
10. 只实现清单需要的协议。若涉及 DeepInfra 核验账单符号、近期消费和欠款；OpenRouter 区分账户 credits 与 Key 限额；New API／One API 核验账户权限、用户 ID 与 quota 换算；兼容 JSON 限已确认接口和受限字段路径，不脚本化、不盲扫。
11. 现存凭证协议保留窗口、模型、来源与可信耗尽／恢复语义；原生与回退同轮不重复调用，所有查询失败统一保留旧成功值。普通 429 或 reset 到期不能伪装权威恢复。
12. 当前清单确需登录会话时，只能经本地已授权连接器验证来源与账户；不导出 Cookie、不接管浏览器、不自动登录／绕验证码。缺通道保留具体阻塞，不把该来源永久排除。
13. 管理服务后台独立运行，每资源正常周期 60 分钟稳定错峰；涵盖人工关闭、自动暂停及所有分页／筛选外目标，不依赖浏览器或 usage 采集。无能力项记录安全结果，不无意义探测。
14. 启动对无观测／已到期目标合并补刷一轮；持久最近尝试、最近成功、下次执行、任务批次和可恢复租约，失败不每 tick 洪泛。公平分片覆盖完整批次，慢来源不阻断其余资源。
15. 默认全局并发 4，同来源 single-flight／限速；每目标总预算默认 15 秒、硬上限 60 秒，响应体上限 2 MiB，重试计入预算，429 遵守 Retry-After。人工刷新不永久推迟后台周期，人工／定时／恢复／巡检共享执行。
16. 状态与能力 GET 不访问上游；POST 刷新返回 202／任务 ID；任务 GET 给排队／执行／完成、目标计数及成功／失败／不支持计数和安全逐项结果，部分失败不报全成功。
17. 管理鉴权、错误封装和旧 API 保持兼容；配置更新校验预期版本，冲突 409。秘密沿用服务端保护，读响应仅 configured，空白保存保持，明确清除独立表达；秘密只在授权查询中最小化使用，不输出到任务／日志／缓存／错误或 Issue。
18. 默认 HTTPS／证书验证、明确批准目标、受控路径与预算。阻断云 metadata、未授权内网、DNS 重绑定与跨源携认证 redirect，覆盖 IPv4／IPv6；私有站按管理员明确范围授权。代理不能绕安全策略，不能把通用 HTTP 调用当成已验证安全边界。
19. 查询不改变推理 Key／base URL、人工状态、优先级或冷却；不发模型生成请求测额度，不领取／充值／重置 credit。

## Testing Decisions

主 seam 为父 #66 确认的管理 API→真实管理服务／临时持久层→隔离 core／受控协议上游；对查询和调度使用受控时钟、网络与故障注入。补协议 fixture 与少量 API／UI 行为测试，不为每个内部解析步骤新增 mock 契约。

- 浏览器与 usage 采集关闭仍覆盖全库存；多页、人工关闭、暂停、无能力、慢／失败来源有可核验结果；补刷／租约／公平与预算正确。
- 人工／定时／恢复来源 single-flight、并发 4、429／Retry-After、超时／超限和任务部分失败；GET 无上游副作用。
- 负数、0、0.1、0.100001、缺字段、无效数值、HTML、错误状态；窗口不变钱、Key 不变钱包，失败保留旧值和成功时间。
- 共享／独立钱包、跨币种和不完整范围；配置重排、重命名、换账户／Key、重建／切实例、配置冲突与迟到结果隔离。
- 秘密诱饵、鉴权、redirect、DNS、内网例外、IPv4／IPv6、代理与来源账户不符的禁止行为；日志与读接口不泄露。
- 当前清单每项授权真实查询、金额／单位展示、小时刷新，并与 A／C 联合验证门禁；fixture／unsupported 或删除失败项不能替代最终验收。

对应父验收 6–11、16–18，并为 2、4–5、8 的策略闭环提供可信观测；父其余要求不取消。

## Out of Scope

不增加市场覆盖率或清单外平台数量指标，不猜接口、不做财务账本或汇率交易；模块不拥有自动门禁。当前轮不实施、读秘密文件、访问 live、部署／重启／合并／关闭 issue，不连接 yosef-server 或处理小电脑 Qwen。
