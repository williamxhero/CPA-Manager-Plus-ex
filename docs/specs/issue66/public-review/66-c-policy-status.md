# [SPEC 66-C] 正交自动策略、统一状态展示与完整链路验收

- 父需求：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。仅派生公开父需求，不缩减原验收。
- 交付类型：规划与消费状态契约提案；不是现有 UI、core 能力、当前库存或部署证明。
- 自动动作消费 66-A 的真实门禁确认与 66-B 的可信观测；品牌复用 [66-D #68](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/68)。

### Use Case

管理员需要在凭证与 provider 的所有适用界面一致地理解人工关闭、精确余额和自动暂停；已启用策略必须真实生效，而不是数据库或前端模拟。

## Problem Statement

公开父 #66 要求把名称前自动标志与原人工开关分开，并增加 provider 余额及独立策略。陈旧数据、共享钱包、未知门禁或应用失败若被当成完整余额／已保护，会误导管理员；仅修一个渲染点也不能完成需求。

## Solution

以同一后端状态呈现人工意图、策略、可信观测、待协调和真实已应用门禁；严格按新成功金额证据执行 ≤0.1 暂停、>0.1 恢复。扩展到全部适用渲染点，并以隔离真实路由及当前清单逐项授权验证交 Hermes 独立验收。

## User Stories

1. 作为管理员，我希望凭证名称前看到自动状态，以便区分人工关闭。
2. 作为管理员，我希望 provider 使用相同状态语言，以便跨页面理解。
3. 作为管理员，我希望自动标志不是另一个滑动开关，以免误操作。
4. 作为管理员，我希望人工关闭在自动恢复后仍保留，以便保留决定。
5. 作为管理员，我希望人工开启不绕过自动暂停，以便保护有效。
6. 作为管理员，我希望余额 ≤0.1 暂停，以免资金不足继续发请求。
7. 作为管理员，我希望只有新成功余额 >0.1 才恢复，以免低正数振荡。
8. 作为管理员，我希望显示舍入不改变策略结果，以便精确边界可信。
9. 作为管理员，我希望失败保留旧值并标陈旧，以免把错误当零或恢复。
10. 作为管理员，我希望钱包范围、币种和不完整数据明确，以免误判整行。
11. 作为管理员，我希望首次 provider 策略明确启用，以免迁移静默关闭资源。
12. 作为管理员，我希望策略 OFF 不隐式恢复历史暂停，以便保持既有语义。
13. 作为管理员，我希望门禁不可用或应用失败可见，以免误信已保护。
14. 作为键盘或触屏用户，我希望不用颜色或 hover 就能读说明，以便无障碍操作。
15. 作为管理员，我希望列表、详情、卡片与监控语义一致，以便可靠排障。
16. 作为维护者，我希望每项真实当前来源都有路由与查询证据，以免局部测试冒充全量交付。

## Implementation Decisions

1. 凭证仍按各 provider 可信窗口判定耗尽／恢复；reset 时间只安排复查，普通 429／网络错不是耗尽或恢复证据。不把货币阈值套给百分比、token 或请求窗口。
2. provider 余额策略与凭证策略、人工开关独立。首次迁移默认 OFF，需明确启用，避免静默关资源；保留公开父需求的策略持久值／有效值／来源／环境锁及旧凭证接口语义。
3. 只有新鲜、成功、同实例／目标身份／来源配置版本且范围可信的金额才能触发；有限负数、0、恰好 0.1 均属于暂停区间。原生币种分别判断，不隐式换汇，显示舍入不参与规则。

| 当前本策略暂停 | 新成功且范围匹配的金额 | 结果 |
|---|---|---|
| 否 | ≤0.1 | 暂停 |
| 否 | >0.1 | 保持未暂停 |
| 是 | >0.1 | 仅解除本策略暂停 |
| 是 | ≤0.1 | 保持暂停 |
| 任意 | 失败／未知／不支持／缺认证／陈旧／错身份或来源版本 | 不因本次查询转换 |

4. 同一 observation 每目标最多消费一次；重复刷新、页面重载和重启不能用同证据反向转换。连续 0.000001／0.05／0.1 保持暂停，只有下一次可信成功 >0.1 才恢复。
5. 共享钱包不重复累计；多个独立来源不跨币种相加。只有全部可路由资金来源范围完整、当前可信且均 ≤0.1 才暂停整行；至少一个明确可路由来源新成功 >0.1 才解除已有整行余额暂停。部分未知不能误停整行。
6. 读取状态分开 manual、policy、观测、自动意图／实际应用确认、原因、证据、时间及协调状态；effective 路由资格必须同时满足原人工／配置、门禁及健康／路由约束，不从本地 bool 宣称可路由。
7. 自动恢复不清人工关或其他限制；人工开不绕门禁；策略 OFF 仅停新动作，不批量恢复历史暂停。若需清历史限制，必须明确、授权、版本化并仅清本归属。
8. 状态至少区分策略未启用、正常监测、自动暂停、自动状态不可用；另表示待协调。失败不乐观成功，应用尚未确认不显示已保护。事件只保留安全目标／原因／证据／金额单位／转换与确认时间，不含秘密或原始个人响应。
9. API 使用 B 的能力／状态／刷新任务，GET 不访问上游；策略更新鉴权并校验版本，界面显示真实有效值／锁和失败。页面不新建另一套查询、timer 或自动策略。
10. 名称前标志提供图形＋可访问名称／说明；原人工开关、名称复制、排序／搜索／选择／详情定位保持兼容。原因、最近成功／失败、下次检查可由鼠标／键盘／触屏查看，未知重置不虚构倒计时。
11. provider 余额显示数值、币种／单位与范围；无历史为未获取，无能力／缺认证如实提示，错误显示旧成功及陈旧时间；unlimited 必须来自明确协议。多钱包展示明细，不用误导总额。
12. 覆盖凭证列表／网格／卡片／详情、provider 桌面／窄屏／详情，以及健康检查、监控／巡检／动作历史等适用消费者；实施时逐点登记验证，不预设源码位置。历史视图明确历史，创建／导入无观测为未知，不增 policy owner。
13. 明暗、窄屏和可访问性保留余额／自动标志／人工操作；不整站重设计。品牌按既有 #68 独立交付，最终验收同时要求品牌通过。
14. writer 自测与 Hermes 独立验收分离；固定 manager／core／构建版本，维护原父全部 18 项结果及阻塞。当前清单每项需真实授权查询、单位、小时刷新及门禁验证，fixture／unsupported／删失败项均非完成证据。

## Testing Decisions

主 seam 沿用父 #66：管理 API→真实管理服务／临时持久层→隔离真实 core→受控协议上游。只 mock 外部网络、时钟与故障注入，不 mock 被验收状态转换或选择器。补用户动作、复制／原开关、状态一致性及可访问性的 React 测试，不依赖私有字段或 CSS 哈希。

- 精确测试 -1、0、0.000001、0.05、0.1、0.100001，显示为 0.10 不改变原值规则；同证据幂等，多轮低正数不振荡。
- 查询失败、401／429、超时、缺字段、HTML、NaN／Infinity、陈旧／错版本不伪造零或转换；恢复仍需可信证据。
- 多 Key 共享、独立钱包、跨币种／部分未知／明确可路由恢复来源判定；不误伤其他 provider。
- 人工关＋自动暂停、人工开＋仍暂停、自动恢复＋人工关、OFF／环境锁／失败及其他归属限制正确。
- 能力不可用、应用失败／超时／重启待协调如实呈现；所有适用界面语义一致、名称前标志不破坏复制或人工操作，明暗／窄屏／键盘／触屏可理解。
- 浏览器关闭后的小时刷新→低余额→真实门禁确认→新请求／重试／故障转移排除→新成功观测恢复→仅清本策略→重新路由；结合 A 的迁移／重启／回退、B 的安全与 D 的品牌全链验证。

对应父验收 1–6、8、11–14、16–18；15 由 D 提供并在最终交接核对，7／9–10 由 B 提供。完整父验收和相关回归不得因分包而遗漏。

## Out of Scope

当前轮不实现 UI／策略／测试、不访问 live、不读或导出秘密、不部署／重启／合并／关闭 issue，不连接 yosef-server 或处理小电脑 Qwen。不变更人工规则、路由优先级、插件 ABI，不增加清单外市场目标、不以推理生成请求测余额。
