# T07：凭证独立自动暂停与可信恢复闭环

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 A／C，仅依据公开父需求；不发布独立项目的源码或调查结论。

### Use Case

凭证额度耗尽时，管理员需要真正阻止新的推理尝试，同时保留人工意图及额度复查；权威恢复后只清本策略暂停。

## What to build

消费独立 core gate，把可信凭证额度证据、持久自动意图、门禁应用确认与名称前标志连成完整链路。若实际 core 缺能力，给出清晰能力阻塞并在目标项目上下文完成依赖，不回退写人工 disabled 或模型排除配置。

## Acceptance criteria

- [ ] 核实目标 core 独立门禁能力／管理契约，以固定验收版本及稳定实例／目标身份绑定；必要修改通过 cross-project-delegation 由目标项目 owner 完成，不在本项目直接改其他仓库。
- [ ] 可信额度耗尽触发独立暂停；reason、owner、evidence、版本与 applied 确认经 API／界面可见。写入／持久失败或超时进入可观察待协调，幂等重试，不谎报保护成功。
- [ ] 隔离真实 core 的两资源 A/B 证明：暂停 A 后新请求、重试、故障转移不再尝试 A，B 正常；已在途请求不强制中断。适用流式／长连接的新尝试亦须遵守 gate。
- [ ] 暂停中额度查询仍可达；只有权威成功恢复窗口才能解除自身暂停，重置时间只是复查计划，普通 429、失败、未知或陈旧缓存不能恢复。
- [ ] 手动关＋自动暂停并存；手动开启不绕暂停，自动恢复不解除人工关闭／其他限制；策略 OFF 不隐式批量恢复，保留旧策略与环境锁兼容。
- [ ] 身份／实例／配置变更、迟到结果、重复证据及并发管理写入不串号或重复转换；秘密诱饵与管理鉴权通过。
- [ ] 管理 API＋临时持久层＋隔离真实路由测试通过，UI 只消费同一确认状态；不以 fixture selector、前端过滤或数据库 bool 替代路由证明。
- [ ] 记录失败协调、升级／回退与启动安全要求；历史迁移另票完成前不得宣称可安全生产替换。Hermes 独立验收及部署授权保留，本轮不实现、不访问 live。
