# T10：所有渲染点的一致状态展示

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 C，仅依据公开父需求。

### Use Case

管理员在列表、详情、监控或手机窄屏查看同一资源时，需要看到一致且不混淆人工开关的自动暂停与余额状态。

## What to build

将已验证的代表性凭证／provider 状态闭环扩展到全部适用消费者。每个界面使用同一后端身份、观测与门禁确认语义；名称前标志不是第二个人工滑动开关。

## Acceptance criteria

- [ ] 逐项登记并覆盖凭证网格／列表／详情、provider 表格／窄屏卡片／详情／健康检查、监控概览／巡检结果／动作历史及创建／导入后状态。历史视图明确历史，不假装当前证据。
- [ ] 人工关闭、自动暂停、未知／能力不可用、待协调与真实已应用保护可区分；名称前标志具备可访问名称和说明，不复用人工控件语义，不仅依靠颜色或 hover。
- [ ] provider 余额列和详情呈现精确原生币种、范围、上次成功与陈旧／失败信息；不支持／需配置不显示零。多来源共享／不完整／跨币种不展示误导总额。
- [ ] 复制名称／Key、人工开关、详情入口和批量选择不受标志事件影响；人工开启不能表现为清除自动暂停，失败操作不乐观伪成功。
- [ ] 所有适用界面可见持久／有效策略、环境锁及失败；查询状态 GET 不发平台请求，刷新接入统一任务，不增加页面私有定时查询旁路。
- [ ] 键盘、触屏、明暗主题与窄屏验证；加载／空值／失败保留旧值、迟到响应／换身份、人工＋自动双状态及门禁不可用有 React 行为与可访问性回归。
- [ ] 以真实管理状态和隔离 core 证明至少一条跨页面暂停→确认→恢复链路；UI 测试不能替代路由证明，不削弱原有有效测试。
- [ ] 保留 API 兼容、增量迁移／回退、Hermes 独立验收与后续部署授权；本轮仅规划。
