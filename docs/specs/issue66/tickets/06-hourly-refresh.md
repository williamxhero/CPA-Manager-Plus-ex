# T06：全量小时刷新与共享任务进度

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 B，仅依据公开父需求。

### Use Case

管理员关闭所有浏览器后，仍需要所有凭证与 provider 按小时更新，且手动刷新能看到同一任务的真实进度。

## What to build

把统一查询投入管理服务后台的全库存小时调度；人工／定时／恢复探针／巡检共用来源级去重、持久任务和安全状态。API 与界面可查看队列、逐项结果及部分失败，单个慢来源不阻塞其他资源。

## Acceptance criteria

- [ ] 浏览器关闭、不登录面板、usage 采集不开时仍每 60 分钟覆盖全部现存凭证和 provider；人工关闭、自动暂停、分页／筛选外资源均在批次快照内。
- [ ] 稳定错峰，首次缺观测／已到期补刷；停机错多小时只合并一轮；尝试／next due 持久化，失败不在每个 tick 洪泛，crash 租约可恢复。
- [ ] 全局默认并发 4、来源 single-flight 与限速；默认总超时 15 秒、硬上限 60 秒、响应体 2 MiB；429 遵守 Retry-After，重试计入预算，超限明确失败。
- [ ] 多标签页、手动与定时共用任务；人工刷新不永久推迟原周期；重复进行中请求可返回同一任务，原生／回退／恢复不重复消费上游。
- [ ] POST 刷新返回 202／任务 ID；GET 任务有目标与成功／失败／不支持计数及安全结果；部分失败不报全成功；状态 GET 无上游副作用。
- [ ] 余额／凭证代表性界面显示最近尝试、最近成功、下次检查及任务进度；没有历史值不变零，失败保留旧成功及时间。
- [ ] API＋临时持久层＋受控时钟／协议上游验证跨页全量、公平、失败隔离、重启、single-flight、并发及 429；不依赖浏览器 timer，不消耗推理额度。
- [ ] 增量升级不清空旧数据，记录备份／回退；Hermes 独立验收与部署授权保留。本轮只规划。
