# T08：provider 精确余额暂停与恢复闭环

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 C，仅依据公开父需求。

### Use Case

管理员希望 provider 在资金 ≤0.1 时独立暂停，只有下一次新鲜可信余额 >0.1 才恢复，并且人工关闭始终保留。

## What to build

把可信金额 observation、独立 provider 自动策略、core 门禁确认和 provider 余额／状态展示贯通。先以一个已支持来源验证完整行为，再由当前清单适配票扩展所需来源；不因策略迁移默认启用而静默关闭资源。

## Acceptance criteria

- [ ] 策略独立于凭证策略和人工开关，首次上线需明确启用；返回持久／有效值、来源、锁及时间，失败不乐观显示成功；策略 OFF 不隐式恢复历史暂停。
- [ ] 精确原生货币金额 ≤0.1（含负数／0／恰好 0.1）暂停，只有下一次成功 >0.1 才清本策略暂停；同证据每目标最多一次，连续 0.05／0.1 不振荡，显示舍入不参与比较、不做隐式汇率换算。
- [ ] 失败／不支持／需配置／陈旧／身份或来源版本不明不改变自动状态；窗口额度不能直接套金额阈值。
- [ ] 共享钱包不重复累计；跨币种不加总；整行全部可路由资金来源须范围完整、新鲜可信且均低余额才暂停，至少一个明确可路由来源新成功 >0.1 才恢复；部分未知不能误停整行。
- [ ] 人工关＋自动暂停同时可见；人工开不绕门禁，自动恢复不清人工关／其他限制。门禁失败显示不可用／待协调，不改 disabled／排除模型伪装。
- [ ] 代表性 provider 列表／详情呈现币种、范围、陈旧状态、名称前非滑动开关标志；读状态、复制、人工操作兼容。
- [ ] API＋临时持久层＋隔离真实 core 验证金额边界、重复／迟到证据、多钱包、人工并发及失败协调；单资源暂停不误伤其他 provider。
- [ ] 余额查询继续可用，记录安全事件而非秘密；增量迁移／回退、Hermes 独立验收及后续显式部署授权保留。本轮只规划。

## Blocked by

- #77 — 凭证独立自动暂停与可信恢复闭环（共享独立门禁消费／确认语义与路由证明基础）。

外部依赖：目标 core 对当前 provider 目标的真实独立 gate 能力，不能以凭证 gate 单独通过推断 provider 已支持。
