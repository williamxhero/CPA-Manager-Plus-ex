# T05：凭证额度接入统一后端查询闭环

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 B，仅依据公开父需求。

### Use Case

管理员需要不依赖浏览器私有查询逻辑即可刷新凭证额度，并在失败后仍能分辨旧成功数据与当前查询错误。

## What to build

将现存凭证可信额度协议接入统一后端查询、观测／任务 API 和凭证展示。先用原生能力，按确认协议回退；保留窗口、模型、身份与来源语义，为后台全量刷新和可信恢复提供同一入口。

## Acceptance criteria

- [ ] 枚举当前本地凭证的查询能力，成功／不支持／需配置如实返回；人工关闭和自动暂停不阻断运维额度查询，不依赖推理 usage 采集。
- [ ] 原生与回退在同一轮不重复查询，现有可信窗口判据保持；货币阈值不套给百分比／token／请求窗口，普通 429 或 reset 到期不伪装权威恢复。
- [ ] API、持久观测与凭证代表性展示形成闭环；错误保留上次成功及时间、更新本次尝试／陈旧状态，所有来源遵守同一失败保留语义。
- [ ] resource／instance／identity／source 配置版本与迟到响应隔离通过；删除重建、换账户／Key、名称／顺序变化不能串用恢复证据。
- [ ] 共享来源调度入口可供人工刷新及恢复探针复用，不保留旁路；不使用模型生成请求测额度，不领取／充值／重置 credit。
- [ ] 临时持久层＋协议上游＋UI 回归覆盖窗口成功／持续耗尽／缺字段／无权限／超时／秘密诱饵，并保留旧 API／策略兼容。
- [ ] 本地 Qwen 等现存来源仅按本地授权条件处理；不连接或替本票处理小电脑 Qwen。缺查询条件具体列阻塞，不伪造完成。
- [ ] 保留增量迁移、回退、Hermes 独立验收及后续部署授权门槛；本轮仅规划。
