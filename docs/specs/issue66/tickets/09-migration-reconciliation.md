# T09：历史迁移、重启协调与安全回退

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 A／C，仅依据公开父需求。

### Use Case

管理员升级或重启后需要保留人工意图与自动保护；回退不能因为旧版本忽略新状态而意外重新放行。

## What to build

将已有自动化数据升级到独立暂停模型，并以重启后的真实路由、管理状态和操作界面验证可恢复协调。提供可演练的备份、失败中止与受控回退方案，而非单独的数据库变更。

## Acceptance criteria

- [ ] 迁移逐条核对资源身份、历史 ownership 与人工变更；只迁移可证明归本策略的记录，模糊来源标待确认，不批量启用历史 disabled 资源。
- [ ] 增量 schema／数据升级保留额度历史、人工配置、秘密保护及现有策略锁；全新库与历史库均可升级，重复执行幂等，失败有明确恢复路径。
- [ ] 启动时先恢复独立门禁，再接受受影响推理流量；恢复失败明确 not-ready／fail-closed，不短暂放行；实际当前运行模式不可为方便验收而排除。
- [ ] durable／desired／applied 的不一致、崩溃点、超时及失联可重试协调；任务租约恢复不重复转换证据，身份变化和删除重建不复活旧暂停。
- [ ] 管理 API 与 UI 显示待协调／不确定及人工状态，不将数据库写入当成真实门禁确认；额度查询和其他不受影响资源不被无端阻断。
- [ ] 回退前检查旧版本能否理解保护状态；无法安全降级则拒绝／停流并要求明确操作，不静默清门禁、不写人工 disabled 作为替代实现；备份恢复与风险提示可演练。
- [ ] 临时历史数据库＋隔离真实 core 覆盖升级、重启、迁移中断、恢复失败、部分 ACK、人工并发及回退；保留既有兼容回归和秘密诱饵测试。
- [ ] Hermes 独立验收、精确 head CI、完整回归和部署授权仍是发布门槛；本轮仅规划、不修改数据或重启服务。
