# T03：当前清单中的官方余额协议补齐

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 B，仅依据公开父需求；不是增加市场覆盖率。

### Use Case

管理员需要当前清单确实使用的官方计费来源给出正确余额，而非把 Key 限额或欠款误当钱包资金。

## What to build

在统一配置→查询→观测→余额展示路径中，补齐当前清单涉及且首来源尚未交付的官方协议。重点为父规格列举的 DeepInfra／OpenRouter 语义；只做清单确认需要的官方路径，不扫描或接入额外平台。相同协议多个来源复用 adapter。

## Acceptance criteria

- [ ] 以 #71 冻结的脱敏当前实例清单明确适用范围，逐项说明官方接口、权限、单位与余额范围。清单不涉及本票协议时，提供可核验“不适用”证据，不虚构接入。
- [ ] 涉及 DeepInfra 时核验账单符号与近期消费，有限欠款返回负可用余额，不能以查询失败长期保留旧正值掩盖欠款。
- [ ] 涉及 OpenRouter 时区分账户 credits 与 Key 限额；账户权限缺失明确需配置，不拿 Key 限额替代账户钱包。
- [ ] 所有适用来源共用精确金额、版本隔离、历史值保留、秘密保护与受控 transport；不新增页面直连或独立调度。
- [ ] 配置／错误状态经 API 和 provider 余额展示可验证；成功、401／429、字段缺失、HTML、符号／单位错误、占位上限及 late response 的协议与 UI 测试通过。
- [ ] 每个适用来源在最终授权窗口验证真实余额／单位、小时刷新和独立暂停恢复；fixture 不是最终交付证明。缺认证列具体阻塞，不删除失败清单项。
- [ ] 本票以当前官方协议族的有限路径为界，不扩展财务功能；若核实清单存在超出单上下文的其他官方协议，先按同一父 SPEC 记录并拆成每个确认协议的跟进票，不把范围藏在本票中。
- [ ] 保留增量存储／回退及 Hermes 独立验收、后续授权部署门槛；本轮不实现或访问 live。
