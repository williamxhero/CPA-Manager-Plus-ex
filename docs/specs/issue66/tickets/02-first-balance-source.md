# T02：首个余额来源的安全查询闭环

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 B，仅依据父公开需求。

### Use Case

管理员需要为当前实例一个已确认来源配置只读查询认证，手动刷新并看见可信金额与单位，不泄露秘密或改变推理配置。

## What to build

交付统一 Go 查询模块的第一个真实协议纵向路径：受控来源配置、服务端秘密引用、精确 observation、任务／状态 API、provider 余额显示。同步冻结本地当前 provider 的脱敏验收清单，供后续适配票判定范围；此票只实现一个已确认所需协议，不承诺其他来源已交付。

## Acceptance criteria

- [ ] Hermes 以安全通道核实实际本地实例、包含人工关闭项的清单、平台／协议、账户范围、单位和查询认证前提；历史配置不是运行证据。缺通道时列明阻塞，不查找或导出凭据，不连接 yosef-server。
- [ ] 对清单首个已确认协议，配置→查询→持久 observation→API→余额显示贯通；fixture 验证协议，授权真实查询属于本地最终验收，不以无权限伪造成功。
- [ ] 查询模块与宿主职责分离；金额用精确十进制字符串，保留合法负数；区分钱包、Key 限额、credit 与额度窗口；空值、失败、NaN／Infinity 不等于零。
- [ ] 成功值与最近尝试分开，失败保留上次成功及时间；显示单位、范围、陈旧／需配置／不支持；共享钱包不重复累计，不跨币种求和。
- [ ] 配置 CAS 冲突明确失败；秘密读响应只有 configured，空白保留、清除有明确意图；身份或来源配置版本改变、迟到结果不能串号。
- [ ] HTTPS／证书、受控目标、DNS 重绑定／metadata／未授权内网阻断、跨源 redirect 认证隔离、响应体／时间预算、日志与错误秘密诱饵通过；私有站仅管理员明确授权范围。
- [ ] API＋临时持久层＋受控协议上游与 UI 行为测试覆盖成功、401、429、HTML、字段缺失、超限、网络失败；GET 状态不隐式查询上游，不更改推理 Key／base URL／人工关闭。
- [ ] 本票不启用自动策略；增量迁移保留旧数据，记录备份／回退，部署与 Hermes 独立验收仍单独授权。本轮仅规划。
