# T04：当前清单中的兼容与授权会话来源补齐

## Parent

- 父 SPEC：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。工作包 B，仅依据公开父需求。

### Use Case

管理员当前使用的兼容站点或必要登录会话来源，也需要以正确账户、权限和单位取得余额，而非被“不支持”永久排除。

## What to build

将当前清单涉及且首来源尚未交付的 New API／One API、受限兼容 JSON 余额来源接入统一配置、任务、API 与余额展示。若该清单确需已登录会话，仅在本地授权可用连接器上接入同一闭环；不获取或导出浏览器认证材料，不自动登录。

## Acceptance criteria

- [ ] 以 #71 当前实例清单确定适用协议和账户范围；不涉及的协议记录清单证据，不能新增站点凑数、删除失败项或把历史配置当当前清单。
- [ ] New API／One API 如适用，区分账户钱包和 Key 额度，核验 user ID、查询权限及原始 quota 换算；推理 Key 不保证可查账户，不猜倍率。
- [ ] 兼容 JSON 如适用，使用已确认接口与受限字段路径，不允许脚本、不盲扫 URL、不把占位 billing 上限当真实钱包。
- [ ] 必需会话连接器如适用，验证来源与账户，经独立授权后才能使用；缺授权／连接器列明确阻塞，不绕验证码、不接管浏览器、不导出 Cookie、不连接小电脑。
- [ ] 精确金额／单位、共享与独立账户范围、错误／陈旧显示、来源版本隔离、秘密读写及 SSRF／redirect 防护均复用统一路径，无新的页面私有查询器。
- [ ] API＋受控协议上游＋UI 验证成功、无权限、单位／账户不符、无效 JSON／HTML、缺字段、超时与秘密诱饵；保留上次成功值，不以失败伪造零或恢复。
- [ ] 本票仅已确认的兼容协议路径；若必要会话连接器或其他协议需要独立上下文，按同一父 SPEC 创建有明确范围的跟进票并记录阻塞，不能在范围未知时把本票标完成。
- [ ] 所有适用来源仍须最终授权真实余额、小时刷新及门禁验收；保留数据迁移／回退和 Hermes 独立验收／部署授权。本轮只规划、不访问 live。

## Blocked by

- #71 — 首个余额来源的安全查询闭环（安全 transport、配置／状态路径和当前清单）。

必要授权会话是该来源的外部前提，不是取消该来源验收的理由。
