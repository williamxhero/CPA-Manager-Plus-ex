# [SPEC 66-B] 统一额度查询与全量小时刷新

- 父规格：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。本子规格保留父规格全部相关要求。
- 状态：规划，未实现、未测试、未部署。GitHub 链接见 [规划总览](./planning.zh-CN.md)。
- 依赖：与 [66-A](./core-gate-contract.zh-CN.md) 共享身份契约；只读查询及调度可先行，真实自动保护依赖 A。当前 provider 清单待 Hermes 安全核实，不能冒用历史配置。

### Use Case

管理员关闭浏览器后，仍需要本地管理服务按小时刷新全部现存凭证与 provider 的可信额度／余额，并安全保留查询历史。

## Problem Statement

现有额度快照主要接收调用方提交的数据，浏览器刷新只覆盖选中或当前页。后台冷却 worker 依赖失败事件及已有 ownership，不能保证浏览器关闭时所有资源每小时更新。AI provider 没有统一账户余额域，百分比快照与浮点数也不能准确承担货币判定。

## Solution

以独立 Go 查询深模块统一协议、认证、精确金额、范围和安全错误；由管理服务统一枚举、保存与调度所有现存资源。手动、每小时及恢复探针共用来源级任务，不重复消耗查询。失败保留上次成功值，缺配置与不支持明确显示而非零余额。

## User Stories

1. 作为管理员，我希望关闭浏览器后额度仍每小时更新，以免依赖页面保持打开。
2. 作为管理员，我希望所有凭证与 provider 包含手动关、自动暂停、分页外目标，以便不存在漏刷。
3. 作为管理员，我希望手动刷新单个或全部资源，以便充值后立即检查。
4. 作为管理员，我希望同一钱包查询去重，以免多 Key 和多标签页重复请求。
5. 作为管理员，我希望看到金额、币种和账户／Key 范围，以免混淆账户钱包与 Key 限额。
6. 作为管理员，我希望负余额如实显示，以免欠款被保留旧正值掩盖。
7. 作为管理员，我希望失败仍保留上次成功值和时间，以便识别陈旧而非零。
8. 作为管理员，我希望缺认证、无接口和未知单位分别报告，以便补齐查询条件。
9. 作为管理员，我希望精确十进制不受显示舍入影响，以便 0.1 边界正确。
10. 作为管理员，我希望改 Key、账户或配置后旧查询结果失效，以免串号。
11. 作为管理员，我希望查询凭据不出现在读响应、日志或任务里，以便保护秘密。
12. 作为管理员，我希望余额端点不能用于内网探测或跨源带出认证，以免形成 SSRF 和秘密泄露。
13. 作为管理员，我希望停机错过多个周期只补一次，以免恢复时洪泛上游。
14. 作为维护者，我希望各个协议的差异封在一个模块中，以免页面复制解析规则。
15. 作为管理员，我希望当前实例每个 provider 都有真实查询与验收记录，以免用“不支持”冒充交付。

## Implementation Decisions

### 查询模块与数据契约

- 模块只暴露列举能力、查询目标、标准化 observation 的宿主操作；内部注入 HTTP transport、凭据解析器、时钟和取消上下文。模块不改路由／策略／推理配置，不依赖桌面 Python、conter_proj 或小电脑。
- 输入绑定不透明 ResourceRef、CPA instance、identity revision、BalanceSource、source configuration revision、超时；输出 observation ID、请求序号、来源／账户范围、采样时间、结果及安全错误码。
- Observation 金额为有界精确十进制字符串（解析时限制长度、位数和指数范围，禁止 NaN／Infinity）；内部使用精确数或定点，不让 float64 参与金额判断。优先标准库精确算术，确有需求再论证新增依赖。
- 区分 account_wallet、key_remaining、credit_balance 与额度窗口。合法负数是欠款；只有协议明确语义才能标 unlimited，负数或占位大上限不等于无限。显示倍率和舍入不参与决策。
- 结果区分 success、unsupported、needs_configuration、auth_error、rate_limited、network_error、parse_error。缺字段、空响应、HTML、success=false、失败均不是零。
- 独立余额实体增量扩展现有 SQLite／repository 边界，不将金额塞进百分比窗口字段，不删除旧快照。记录最近尝试、最近成功、下次到期、租约、任务批次及单目标安全结果。
- ResourceRef 不采用前端 render key、明文 Key、名称或位置；采用 A 的稳定绑定。source／account 变更、换 Key、删除重建或切实例使旧观测不可决策；同版本查询亦以单调序号阻止迟到覆盖。名称／显示倍率不改变钱包归属。
- 查询历史 identity 不等于路由 identity。复用现有严格 locator，但不能据历史可延续规则自动给新身份应用暂停。

### 钱包范围与实际适配

- 一个确认的真实账户钱包只对应一个 BalanceSource，可被多行引用；不能只凭相同 host 判断共享账户。来源级 single-flight 的键包含实例、确认账户范围及来源配置版本，不能在不同账户／权限间错误复用。
- 多钱包明细保留；仅同币种、互不重叠且范围完整可汇总。不跨币种相加，不把部分已知展示成整行完整余额。
- 当前 frontend 有九类额度配置，snapshot 接收支持与其不完全相同，且 Qwen 失败会清 payload。后端化必须逐能力核对，不宣称已有统一持久化／失败保留能力。本需求统一旧值保留，Qwen 不得沿用清空失败数据的例外。
- 复用可信凭证原生 quota／已知协议回退，保留各 provider 窗口耗尽恢复证据。同轮不重复原生与回退查询；不能用模型生成请求测额度。
- Hermes 通过安全认证通道核实本地当前运行实例，给出脱敏资源 ID、平台／协议、账户范围、单位、认证前提、实际模式和接口证据。包括人工关闭项。未核实记为阻塞，不读取历史配置代替、不猜测平台。
- 只实现该清单需要的 adapter。DeepInfra 如涉及须核验账单符号、recent 与欠款；OpenRouter 如涉及区分账户 credits 与 Key 限额；New API／One API 如涉及核验账户凭据、user ID、quota 换算。兼容 JSON 仅文档已确认的受限点分路径，不允许脚本、不盲扫端点。
- 若清单要求授权会话连接器，保留其必交范围：只能本地经授权连接器、验证来源与账户，不导出 Cookie、不接管浏览器、不自动登录／绕验证码。通道缺失是该项交付阻塞，不永久排除。

### 统一调度与任务 API

- 管理服务启动独立后台 worker，不依赖 usage 采集开关或浏览器；枚举批次快照内所有现存凭证和 provider，包括 disabled／自动暂停和所有分页。缺能力也记录安全结果，不做无意义探测。
- 每资源正常周期 60 分钟，使用稳定相位错峰，下一次 schedule 基于后台周期而非每次手动刷新时间。首次无观测或已到期补刷；错过多个周期合并一轮。记录尝试／next due，不能每个 tick 因最近成功较早而重试。
- 全局并发默认 4，同来源 single-flight 与速率限制；默认目标总预算 15 秒、硬上限 60 秒、响应体 2 MiB。超限必须是显式失败，不截断后当成功。重试计入总预算，429 遵守 Retry-After，超出预算安排未来到期而非占槽等待。
- 稳定调度应有公平队列和分片游标，失败单项不能阻塞后续页；租约在 crash 后可回收。重启只补到期目标，多个手动／定时触发返回同一进行中任务或共享该目标执行结果。
- 前端人工查询、恢复探针和巡检均接宿主来源调度，不保留可绕去重的第二套上游执行路径。来源刷新一次可给同轮各关联目标生成绑定各自版本的结果。
- API 沿用管理员认证与错误封装：GET 能力／资源状态不访问上游；POST 刷新支持全部／凭证／provider／稳定 ID，返回 202 和任务 ID；GET 任务返回排队／执行／完成与成功、失败、不支持统计及安全逐项结果；部分失败不能报全成功。
- 配置更新带 expected configuration revision，冲突 409。秘密空白保存保持，清除用明确意图；读响应仅返回 configured。旧客户端及既有手动接口保持兼容。

### 查询 transport 与秘密保护

- 沿用服务端 secret protector 与引用式解析，秘密只在最小执行窗口注入。数据库、响应、任务、日志、错误不保存原始响应、认证头、Cookie、完整 Key 或个人元数据；原有 err.Error() 响应链前必须已安全归类。
- 不直接复用宽松 CPA client／通用 api-call 作为余额安全边界。默认 HTTPS、校验证书，限定管理员批准的 origin／协议，拒绝不明 host 自动发 Key；路径由已知 adapter 控制。
- 默认禁止 redirect；确需同源 redirect 时逐跳重新验证，不允许带秘密跨源。连接时校验解析 IP 并绑定校验结果，阻断 metadata、loopback、link-local、未授权私网、混合 DNS 结果及重绑定；IPv4／IPv6 均覆盖。
- 私有自建站只按管理员明确批准的 host／端口／地址范围放行，不全局关闭 SSRF。代理也不能绕安全策略；无法保证受控代理解析与目标限制则该余额源 fail-closed。测试用本地上游需要显式隔离授权，不扩大生产默认许可。

## Testing Decisions

主 seam 为管理 API 驱动真实服务与临时 SQLite，fake clock 推进小时，协议上游使用 httptest。保留原有 probe、快照幂等、identity late-response 测试的模式；补协议测试但不重复 mock 每层内部结构。

验收覆盖：

1. 浏览器全关、usage 采集关闭，60 分钟仍覆盖全部批次资源，跨分页、disabled、自动暂停、缺能力均有结果；失败单项不饿死其他目标。
2. 重启／crash 租约、到期补刷、漏多小时合并、手动不推迟周期、定时／人工／恢复同源 single-flight、并发 4、429／Retry-After／超时／超限安全生效。
3. 负数、0、0.1、0.100001、超精度及大金额精确，窗口不变钱、Key 不变钱包、无限需明确；失败保留旧成功值／时间并标陈旧。
4. 配置重排、名称变化、换 Key／账户、删除重建、实例切换、source revision 变化和迟到响应不串号；GET 无网络副作用，CAS 冲突不覆写。
5. 共享钱包不重复累计，独立钱包／币种不混合，范围不完整明确呈现；当前清单逐协议合成 fixture 覆盖权限、字段、符号及单位。
6. secret canary 在请求白名单以外、读响应、日志、任务、错误、缓存均不泄露；401、HTML、超限、跨源 redirect、DNS 重绑定、IPv6、私网例外与代理限制有禁止行为断言。
7. 当前清单逐项完成授权真实余额、金额／单位、小时刷新及配合 A／C 自动暂停恢复；仅 fixture、unsupported 或删掉失败项不能算完成。

## Out of Scope

不增市场覆盖率或额外平台数量指标，不读取凭据文件、不联系 live、不连接 yosef-server；不实现充值、领取、汇率换算、财务账本或猜测接口。模块不直接拥有自动门禁或人工开关，不改变第三方插件 ABI。

## Further Notes

- 推荐默认值沿用父 SPEC（60 分钟／4 并发／15 秒／60 秒硬上限／2 MiB），理由是兼容已确认预算而非引入新选择。
- 当前实例清单、接口文档和必要认证权限是按适配项的精确阻塞；不能无限等清单而停止独立架构工作，也不能在清单缺失时假定适配已齐。
- 部署门槛：增量迁移不清空生产库，备份与回退演练；先只读刷新验证，再按 C 显式启用 provider 自动策略；当前清单逐项及 Hermes 独立验收通过后方可宣称完整交付。本轮无上线授权。
