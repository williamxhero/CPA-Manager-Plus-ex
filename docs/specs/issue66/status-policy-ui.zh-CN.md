# [SPEC 66-C] 自动策略、余额展示与本地完整链路验收

- 父规格：[#66](https://github.com/williamxhero/CPA-Manager-Plus-ex/issues/66)。不缩减父规格要求。
- 状态：规划，未实现、未测试、未部署。GitHub 链接见 [规划总览](./planning.zh-CN.md)。
- 依赖：[66-A](./core-gate-contract.zh-CN.md) 提供真实门禁及迁移，[66-B](./balance-refresh.zh-CN.md) 提供精确观测、身份、来源与任务；只读展示可先行但不代表自动保护已完成。[66-D](./brand-regions.zh-CN.md) 独立交付，父规格最终验收同时需要。

### Use Case

管理员需要在所有凭证与 provider 渲染点同时理解手动状态、余额与已确认的自动暂停，避免把低余额、陈旧数据或门禁失败误当正常保护。

## Problem Statement

用户目前主要看到手动开关，无法明确知道是否为额度／余额自动暂停。provider 列表无统一余额与独立策略，多钱包、陈旧值、未知门禁容易被误解为完整余额和有效保护。只改某一表格分支也会令卡片、详情与监控显示相互矛盾。

## Solution

名称前显示与人工开关正交的自动状态标志，provider 展示余额及其语义／单位／陈旧状态。余额策略严格使用可信新观测和十进制边界，经真实 gate ACK 才宣称保护生效。保留原手动行为，最终用本地隔离路由和当前 provider 逐项授权验收证明整个用户场景。

## User Stories

1. 作为管理员，我希望凭证名称前看到自动状态，以便区别人工关闭。
2. 作为管理员，我希望 provider 名称前使用相同状态语言，以便一致理解。
3. 作为管理员，我希望桌面与窄屏都有余额、状态和人工操作，以免核心控件被挤掉。
4. 作为键盘或触屏用户，我希望不依赖颜色与 hover 即能查看原因和检查时间，以便无障碍使用。
5. 作为管理员，我希望旧成功值与失败／陈旧状态同时呈现，以免误认为当前可信余额。
6. 作为管理员，我希望看到币种、账户范围及多钱包详情，以免被不完整总额误导。
7. 作为管理员，我希望 ≤0.1 暂停、只有新成功余额 >0.1 才恢复，以免低正数反复启停。
8. 作为管理员，我希望人工关闭在自动恢复后仍关闭，以便保留人工决定。
9. 作为管理员，我希望人工开启不绕过自动暂停，以便保护规则真正生效。
10. 作为管理员，我希望首次上线 provider 策略需明确启用，以免迁移突然关闭资源。
11. 作为管理员，我希望策略关闭不会静默批量恢复历史暂停，以免改变现有语义。
12. 作为管理员，我希望 core 不支持或应用失败时标记不可用／待协调，以免把 desired bool 当有效保护。
13. 作为管理员，我希望详情、监控与列表不会对同一资源互报矛盾状态，以便排障。
14. 作为维护者，我希望实际本地 provider 每项都有完整验收，以免界面和 fixture 通过被当成全量交付。

## Implementation Decisions

### 自动策略与状态机

- 凭证保留现有 provider 可信额度窗口的耗尽／恢复判断；重置时间只触发复查，普通 429／网络错不是可信额度耗尽。provider 金额策略独立于旧凭证策略，不将金额阈值套给 token／百分比。
- provider 策略默认迁移为 OFF，管理员后续明确启用；理由是父规格禁止静默改变生产资源，而非本轮要求人工选方案。保留策略持久值、effective 值、source、环境锁和更新时间的对外模式。
- 新鲜、success、同 instance／resource identity／source config version、完整可信范围的有限金额才可触发。≤0.1（含负数、0、0.1）暂停；>0.1 才解除本策略暂停。显示舍入不参与比较，不做汇率换算。
- 同一次 observation 每目标最多一次转换；持续 0.05／0.1 多轮保持暂停。失败、unsupported、需配置、陈旧缓存、身份／单位未知均不改变自动状态。
- 整行多 Key provider：只有全部可路由资金来源完整、明确且新鲜可信，并且均 ≤0.1 才暂停整行；至少一个明确可路由来源以新成功观测 >0.1 方可解除已有余额暂停。部分未知不自动整行关闭；不重复累计共享钱包、不跨币种相加。
- state response 分开给 manual、policy、desired suspension、applied suspension、reason／owner、evidence、last success／attempt、next check、capability／reconciliation。effective qualification 必须尊重 A 的确认与原约束；不能从本地 bool 推导全局可路由。
- 关闭策略停止新动作，不自动清历史暂停；如需清除使用明确操作，版本化且只清本 owner。保留旧手动 API 语义和自动期间的人工修改。
- 事件只记录不透明目标、旧新状态、reason、evidence ID、金额／单位、core 确认与时间，不含查询秘密或原始上游响应。

### API 与 UI 表达

- 使用 B 的能力／状态／任务 API，页面不再直接执行另一套钱包查询。独立 provider 策略更新沿用管理员认证及 CAS，失败不乐观显示成功；手动刷新显示去重后的任务进度与部分失败。
- 至少区分策略未启用、监测正常、自动暂停、自动状态不可用；另可显示待协调。人工关闭可与任何自动状态并存。名称前标志是状态显示，不是另一个滑动开关。
- 名称复制目标不含标志／原因文本；排序、搜索、选择、分页、详情定位与旧操作保持兼容。未知 reset 不显示虚构倒计时。
- 余额显示金额和币种／单位；无历史为“未获取”，无能力／缺认证为“不支持／需配置”，失败保留旧值并标“上次成功／已过期”。unlimited 只接受明确协议证据。
- 不完整多钱包显示范围与详情，不用误导性的单总数。自有状态图形与可访问文字不只靠颜色区分；支持鼠标、键盘和触屏，明暗主题和约 400px 宽度均可用。
- 完整渲染清单与源码定位单独维护在规划总览，避免本 SPEC 设计决策绑定易变路径。必须覆盖凭证列表／网格／详情、provider 表格／窄屏／详情、健康检查组，并对监控账号概览、巡检结果、动作候选历史显示进行一致性核对。
- 历史证据不是当前有效门禁状态，监控／历史页不得把旧 enabled 字段当实时“可路由”；只消费同一状态源，不新增 policy owner。创建／导入流程无既存余额时显示未知，不伪造零。

### 最终验收所有权

- Hermes coordinator 对实现 PR 精确 head 独立验收；writer 自测不等于验收／合并／部署。
- 集成应固定 manager／core revision、能力、测试工具与临时数据，不将现有管理 stub 当真实 selector 证明。生产窗口另行授权，不以本轮规划或既有“只发布规格”永久阻止后续已授权开发。

## Testing Decisions

主 seam 仍为管理 API → 真实 manager／临时 SQLite → 隔离 core／受控上游，不新增按层重复的 mock 体系。React 行为测试覆盖 UI 的用户动作与可访问语义，不匹配 CSS 哈希。复用 provider 原索引操作映射、quota late-response、policy locked／error、ownership fail-closed 既有测试组织。

验收覆盖：

1. 精确金额 -1、0、0.000001、0.05、0.1、0.100001；相同 evidence 幂等；连续低正数不恢复；下一次新成功 >0.1 才恢复；显示成 0.10 仍按原值判定。
2. 查失败、401／429、缺字段、NaN、陈旧／错版本均不触发暂停或恢复；窗口恢复仍需权威证据。
3. 共享钱包、不同币种、多个独立来源及部分未知，整行判定正确且不影响其他 provider。
4. 人工关＋自动暂停、人工开＋仍暂停、自动恢复＋人工关、策略 OFF 保留历史暂停、明确清除只清本 owner、环境锁与请求失败均正确。
5. 缺 core 能力、门禁应用失败／超时／重启协调失败明确可见，不能呈现“已保护”；GET 状态不触发上游查询。
6. 凭证网格／列表／详情及 provider 桌面／窄屏／详情、健康组显示一致，名称前标志不破坏复制和原手动操作；监控及历史不会误报当前资格。
7. 键盘／触屏可读原因、最近成功／失败与下次检查，明暗／窄屏保留核心字段；金额原始值与展示单位一致。
8. 结合 A／B 跑浏览器关闭的小时刷新→低余额真实 gate→新请求／重试排除→充值模拟新观测→只清本 owner→路由恢复；A/B 可用资源隔离正确。
9. 当前实例清单逐项记录真实授权查询、金额单位、小时刷新及独立暂停／恢复；缺权限／会话／模式能力明确阻塞，不能以“unsupported”或 fixture 完成。
10. 父规格所有 18 项验收和相关既有回归由总览矩阵追踪，迁移／回退／安全和品牌均不能遗漏。

## Out of Scope

不整站视觉重做，不新建第二套钱包查询／policy，不改原人工规则、优先级、插件 ABI；不访问 live 或 yosef-server，不消耗推理额度测余额。本轮不实现 UI、策略或测试代码。
